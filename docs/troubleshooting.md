# 문제 해결 및 검증 기록

- 개발 과정에서 발생한 문제와 원인을 확인한 근거,
- 수정 내용 및 재검증 결과를 기록한다.

- 현재는 첫 장애 이벤트의 수신과 DB 저장을 확인한 단계다.
실패 상황과 데이터 정합성에 대한 검증은 이후 추가한다.

## 1. 개발 환경 문제 해결 요약

| 문제 | 확인한 원인 | 조치 및 확인 결과 |
| --- | --- | --- |
| DB 접속 시 의도한 계정이 사용되지 않음 | datasource 사용자명 설정 키의 오타 | 설정을 수정한 뒤 프로젝트 전용 DB 연결 성공 |
| 서버가 시작되지 않음 | 기존 프로젝트 프로세스가 8081 포트를 사용 중 | 실행 명령으로 해당 프로세스를 확인하고 종료한 뒤 서버 시작 성공 |

위 항목은 개발 환경 구성 중 해결한 문제로,
포트폴리오의 대표 기술 사례와 구분한다.

## 2. 현재 확인한 정상 동작

결제 API의 장애 알림을 가정한 테스트 요청을 직접 전송했다.
실제 결제 서비스에서 발생하거나 자동 감지한 장애는 아니다.

### 확인 결과

- 이벤트 수신 API가 HTTP 201을 반환했다.
- 응답에 eventId, incidentId, OPEN 상태가 포함됐다.
- incidents와 events 테이블에 각각 데이터가 저장됐다.
- events.incident_id가 생성된 incidents.id를 참조했다.
- 응답의 수신 시각과 DB에 저장된 시각이 일치했다.

### 확인 범위의 한계

정상 요청 한 건의 처리 결과를 확인했다.
이 결과만으로 중간 실패 시 롤백이나 동시 요청의 안전성을
검증했다고 판단하지 않는다.

## 3. 추가 검증이 필요한 항목

아래 항목은 검증 계획이며, 해결 완료 사례가 아니다.

- 잘못된 입력에 HTTP 400을 반환하고 데이터가 저장되지 않는지
- 사건 저장 후 이벤트 저장이 실패하면 두 변경이 함께 롤백되는지
- 같은 이벤트가 반복 수신될 때 적용할 중복 처리 규칙
- 동시에 요청이 들어와도 중복 처리 규칙이 유지되는지

## 4. 기술 사례 작성 기준

실제로 재현하고 검증한 문제는 다음 순서로 추가한다.

1. 문제와 영향
2. 재현 조건
3. 원인을 찾은 근거
4. 검토한 해결 방법과 선택 이유
5. 구현한 변경
6. 재검증 결과
7. 남은 한계

관련 코드, 테스트, 커밋이 있으면 함께 연결한다.
